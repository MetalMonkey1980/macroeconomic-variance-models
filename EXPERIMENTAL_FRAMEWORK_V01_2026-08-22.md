# Metal Monkey — Experimental Framework

**Version:** V01  
**Date:** 2026-08-22  
**Status:** Experimental / Open  
**Related:** Council of 60 / Perspective Principle / Seed of Perspective / Personality Test

---

## 1. Purpose

This document defines the first experimental framework for investigating whether the Council of 60 can reveal meaningful differences and connections between human perspectives.

The first investigation begins with the **Metal Monkey position**.

The purpose is not to prove that the Metal Monkey archetype is correct.

The purpose is to observe whether people associated with this position show patterns of preference, perception or response that are:

- repeatable,
- distinguishable,
- comparable with other Council positions,
- and potentially useful for understanding differences between perspectives.

The model may be supported, modified or rejected by the observations.

---

## 2. The Starting Question

The first question is not:

> "What is a Metal Monkey?"

It is:

> **"What, if anything, distinguishes the observed perspective of people associated with Metal Monkey from other Council positions?"**

A second question follows:

> **"What does Metal Monkey share with other positions?"**

And a third:

> **"Where might Metal Monkey act as a bridge between otherwise different perspectives?"**

---

## 3. An Important Distinction

This experiment must distinguish between two different things:

### Expected characteristics

Characteristics that the current Metal Monkey concept predicts or suggests.

### Observed characteristics

Characteristics that appear in the collected responses and survive comparison.

These must never be treated as the same thing.

A characteristic is not evidence simply because it was expected.

> **Do not define the Metal Monkey profile before observing the data.**

---

# 4. The Council Position

For the first experiment, the starting position is:

**Metal Monkey**

The position should be described through the layers currently used by the Council model.

| Layer | Question |
|---|---|
| Animal | What does the Monkey layer represent? |
| Element | What does Metal contribute? |
| Yin / Yang | What direction of energy is represented? |
| Trigon | What shared foundation exists with the other positions in the same trigon? |
| Other relationships | What additional connections exist within the Council? |

These interpretations are working hypotheses.

They must not automatically become scoring rules.

---

# 5. The Circle Around Metal Monkey

The first experiment should investigate Metal Monkey from several directions rather than comparing it only with the entire Council.

## Layer 1 — Same Trigon

Compare Metal Monkey with the other Council positions within the same trigon.

Questions:

- What do the three positions appear to share?
- Where do they differ?
- Are there preferences common to the entire trigon?
- Are there characteristics that appear specifically in Metal Monkey?

---

## Layer 2 — Same Animal

Compare Metal Monkey with other Monkey positions across different elements.

Questions:

- Does the Monkey layer appear to produce recurring preferences?
- Are these preferences stronger than differences caused by the element?
- Does Metal Monkey remain recognizably different from other Monkey positions?

---

## Layer 3 — Same Element

Compare Metal Monkey with other Metal positions.

Questions:

- Does Metal appear to correspond with recurring preferences?
- Are these preferences stronger than the animal differences?
- Does Metal Monkey share characteristics with Metal positions outside its own trigon?

---

## Layer 4 — Yin / Yang

Compare Metal Monkey with positions sharing the same Yin / Yang direction.

Questions:

- Are there observable similarities in the way people approach situations?
- Does Yin / Yang explain patterns that animal or element do not?

---

## Layer 5 — Full Council

Finally compare Metal Monkey with all other Council positions.

The purpose is not simply to rank similarity.

The purpose is to discover:

- clusters,
- distances,
- unexpected similarities,
- unexpected differences,
- and possible bridges.

---

# 6. What Are We Measuring?

The word "perspective" is useful philosophically but is too broad for an experiment.

The experiment therefore needs observable dimensions.

Possible dimensions include:

- risk vs. caution,
- independence vs. cooperation,
- stability vs. change,
- recognition vs. privacy,
- exploration vs. preservation,
- competition vs. harmony,
- directness vs. reflection,
- structure vs. flexibility,
- certainty vs. curiosity,
- individual achievement vs. collective outcome.

These are examples, not final dimensions.

The final dimensions must be defined before the main analysis begins.

A question should only be included if we can explain:

> **What aspect of perspective is this question attempting to observe?**

---

# 7. Question Design

Each test question should have a documented purpose.

For every question we should record:

| Field | Description |
|---|---|
| Question ID | Unique identifier |
| Scenario | Situation presented to participant |
| Options | Available choices |
| Perspective dimension | What the question attempts to observe |
| Expected pattern | What the current model predicts |
| Alternative explanation | Other reasons someone may choose an answer |
| Ambiguities | Known problems with the question |
| Status | Draft / tested / accepted / rejected |

Questions must not be written merely to produce a desired Metal Monkey result.

---

# 8. The Test Should Create Genuine Choices

The test should present choices that are meaningful to different people.

An option should not be deliberately written as:

- stupid,
- weak,
- immoral,
- cowardly,
- ridiculous,
- or socially inferior.

The objective is to observe attraction between legitimate alternatives.

A participant should be able to choose one option while understanding why another person could reasonably choose another.

This supports the central principle:

> **Difference without contempt.**

---

# 9. The First Participant

The first participant associated with Metal Monkey should be treated as an **exploratory case**, not as proof of the Metal Monkey profile.

One person can help us:

- identify interesting questions,
- identify ambiguities,
- discover unexpected preferences,
- test the usability of the questionnaire,
- and generate hypotheses.

One person cannot establish a stable archetype.

Therefore:

> **The first Metal Monkey participant is a source of hypotheses, not validation.**

---

# 10. Expected vs. Observed

Before analysing responses, create an explicit hypothesis record.

Example:

| Dimension | Expected | Observed | Status |
|---|---|---|---|
| Risk / caution | Unknown | Unknown | Open |
| Independence / cooperation | Unknown | Unknown | Open |
| Stability / change | Unknown | Unknown | Open |
| Recognition / privacy | Unknown | Unknown | Open |
| Structure / flexibility | Unknown | Unknown | Open |

The "Expected" column may contain a hypothesis derived from existing Metal Monkey material.

The "Observed" column must be filled only after collecting responses.

The two columns must never be silently merged.

---

# 11. Similarity

We need to distinguish at least four kinds of similarity.

### 1. Within-position similarity

Do people associated with the same Council position show similar response patterns?

### 2. Trigon similarity

Do positions within the same trigon show greater similarity?

### 3. Layer similarity

Do people sharing an animal, element or Yin/Yang direction show similarity?

### 4. Cross-layer similarity

Can two positions be similar even when they do not share the same obvious structural layer?

This last category is particularly important for the concept of bridges.

---

# 12. Distance

Similarity alone is not enough.

The experiment should also investigate **perspective distance**.

For each pair of Council positions we may eventually estimate:

- high similarity,
- moderate similarity,
- low similarity,
- or strong difference.

The exact mathematical method is not yet defined.

It should be chosen only after the response data and question structure are understood.

The goal is not to manufacture a numerical distance merely because the model contains 60 positions.

A distance measure must correspond to observable data.

---

# 13. Bridges

The Council is intended to explore not only similarity but also connections.

A bridge may exist when two positions are different overall but share a meaningful perspective along one dimension.

For example:

```text
Metal Monkey
      |
      | shared response to uncertainty
      |
      +------ Position A

Metal Monkey
      |
      | shared preference for independence
      |
      +------ Position B
Metal Monkey
      |
      | complementary perspective
      |
      +------ Position C

A bridge should therefore be described by what is shared, not merely by the fact that two positions are connected.

## 14. Direct and Indirect Bridges

Not every connection needs to be direct.

A possible structure is:

    Metal Monkey
          |
          v
    Position A
          |
          v
    Position B

If Metal Monkey and Position B are difficult to understand directly, Position A may provide an intermediate perspective.

This is one of the ideas that the Council of 60 should eventually be able to investigate.

However, this is currently a hypothesis.

It must not be presented as an established property of the system.

---

## 15. The First Experimental Questions

The first experiment should attempt to answer a small number of questions.

### Question A

**Does the Metal Monkey participant show a recognizable pattern of preferences?**

### Question B

**Which observed preferences are specific to Metal Monkey, and which appear elsewhere in the Council?**

### Question C

**Are similarities stronger within the same trigon, animal, element or Yin / Yang layer?**

### Question D

**Are there meaningful similarities between structurally distant positions?**

### Question E

**Can these similarities be interpreted as potential bridges between perspectives?**

---

## 16. What Would Count as Interesting?

A result is interesting if it was:

- observable,
- repeatable,
- distinguishable from baseline,
- not dependent on the wording of one question,
- and not introduced after seeing the result.

Unexpected findings are especially valuable.

A result that contradicts the current model is not a failure of the experiment.

It may be a failure of the model.

---

## 17. What Would Count as Failure?

The experiment should be allowed to conclude that:

- no stable Metal Monkey pattern was found,
- different questions produced contradictory results,
- the proposed dimensions were poorly defined,
- Council layers did not explain observed similarities,
- or the model performed no better than a suitable baseline.

These outcomes must remain legitimate.

> **The experiment is successful even when the hypothesis is not.**

The purpose is to discover what is actually there.

---

## 18. Baseline

No pattern should be considered meaningful without comparison.

Possible baselines may include:

- random Council assignment,
- random pairing of participants,
- overall population response distribution,
- comparison with alternative grouping methods.

The final baseline method must be selected before the main analysis.

---

## 19. Avoiding Confirmation Bias

The experiment should follow:

> **Question → Data → Observation → Pattern → Hypothesis**

not:

> **Model → Desired Evidence → Confirmation**

To reduce confirmation bias:

1. Questions should be defined before analysing results.
2. Scoring rules should be documented.
3. Expected characteristics should be recorded separately.
4. Unexpected results must be preserved.
5. Failed hypotheses must not be silently removed.
6. Changes to the model must be documented.
7. Original data should remain available in an anonymized form where ethically possible.

---

## 20. Reproducibility

Every major experiment should eventually record:

- test version,
- question version,
- scoring version,
- dataset version,
- Council mapping version,
- analysis version,
- date,
- assumptions,
- exclusions,
- and final results.

If the analysis is later performed with Python, the code should be versioned alongside the experiment.

The goal is that another person can understand:

> **What was asked → who answered → how answers were interpreted → how the result was calculated.**

---

## 21. The First Data Structure

Before writing an analyzer, we should define the data structure.

A future participant record may eventually contain fields such as:

    participant_id
    council_position
    animal
    element
    yin_yang
    trigon
    question_id
    answer
    timestamp
    test_version

Personal identifying information should not be stored unless it is genuinely necessary.

The research dataset should use anonymous identifiers wherever possible.

---

## 22. The First Experiment Is Exploratory

The first experiment should not attempt to validate the entire Council of 60.

Its purpose is to learn how the test behaves.

The first cycle should therefore be:

    Design
       ↓
    Small pilot
       ↓
    Observe
       ↓
    Find ambiguities
       ↓
    Revise questions
       ↓
    Repeat
       ↓
    Larger dataset
       ↓
    Formal analysis

A pilot result should not automatically be treated as evidence for the final model.

---

## 23. Proposed Development Path

### Phase 1 — Define

- define perspective dimensions,
- document current Metal Monkey hypotheses,
- define Council relationships,
- design initial questions.

### Phase 2 — Pilot

- test questions with a small number of participants,
- identify ambiguity,
- record unexpected interpretations,
- revise the questionnaire.

### Phase 3 — Observe

- collect responses,
- preserve raw data,
- avoid changing the model during collection.

### Phase 4 — Compare

Compare:

- Metal Monkey,
- same trigon,
- same animal,
- same element,
- same Yin / Yang,
- other Council positions,
- baseline groups.

### Phase 5 — Map

Create a preliminary map of:

- similarities,
- differences,
- distances,
- and potential bridges.

### Phase 6 — Evaluate

Ask:

> Did the observations support the current model?

> Did they contradict it?

> Did they reveal something the model did not predict?

### Phase 7 — Revise

Only after the observations are documented should the model be changed.

---

## 24. When Should `data_analyzer.py` Be Written?

The analyzer should not be the first step.

It becomes useful when:

1. the questions are defined,
2. the answer structure is stable,
3. the Council mapping is documented,
4. the dataset structure is defined,
5. the baseline is defined,
6. and we know what we actually want to calculate.

At that point, the Python code becomes an implementation of a documented experiment rather than a tool searching for patterns without a defined purpose.

## 25. Current Open Questions

The following questions remain unresolved:

- What exactly constitutes a "perspective" in the data?
- Which dimensions should the first test measure?
- How many questions are needed per dimension?
- Should participants see only scenarios, quotations, or both?
- How should ambiguous answers be handled?
- How should multiple motivations within one answer be represented?
- How should Council positions be encoded?
- What similarity measure is appropriate?
- What baseline should be used?
- How large should the pilot be?
- How many participants are needed before comparing Council positions?
- Which observations should be considered meaningful?
- How can potential bridges be distinguished from random similarity?

These questions are not defects in the project.

They are part of the experiment.
